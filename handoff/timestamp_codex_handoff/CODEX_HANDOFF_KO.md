# Codex 구현 인계

## 목표와 범위

사진 위에 원본 타임스탬프와 비슷한 위치·모양의 로고, 한국어 날짜·시간을 합성한다. 사용자는 날짜·시간을 자유롭게 설정할 수 있어야 한다. UI 플랫폼은 아직 미정이다. 우선 플랫폼과 무관한 렌더링 핵심부터 설계하는 것이 좋다.

형식 예:

```text
2026년 11월 17일 (화)
오전 3:55
```

사진은 기본 1:1이고 기준 크기는 3240 × 3240이다. 세로형이나 가로형 사진의 자르기·여백 정책은 사용자가 정하지 않았다. 먼저 정사각형 입력을 지원하고, 확장은 별도 결정한다.

## 어떤 리소스를 사용할지

- `metadata/manifest.json`의 `canonical` 키를 사용해 대표 자산을 찾는다.
- `date_glyph`와 `time_glyph`는 같은 숫자여도 별개로 취급한다.
- `weekday_token`은 괄호가 포함된 `(월)` 같은 전체 블록이다. 특히 `(일)`은 수직 투영상 일부 획이 분리되거나 괄호와 가까워, 전체 블록을 보존하는 편이 안전하다.
- `period_token`은 `오전` 또는 `오후` 전체 블록이다. 필요하면 시간용 한글 개별 이미지도 사용할 수 있다.
- 로고는 `assets/logo.png` 한 장에 TIME STAMP 글자와 시계·소인 아이콘이 함께 있다.
- 대표 이미지는 반복 출현 중 여백이 넉넉한 샘플을 택하고 투명 여백을 줄인 것이다. 가장 정확한 위치별 변형이 필요하면 `metadata/occurrences.json`과 출현별 PNG를 비교한다.
- `assets/reference_overlays/`는 고정된 8가지 날짜·시간의 기준 결과다. 날짜를 바꾸는 기능 자체가 구현된 것은 아니다.

## 좌표와 알파

일반 `source_box`는 `[left, top, right, bottom)` 픽셀 좌표이고 오른쪽·아래는 포함하지 않는다. atlas의 `rect`만 `[x, y, width, height]`이다.

추출 PNG는 RGB를 흰색으로 두고 검정 샘플의 밝기를 알파로 사용했다. 검정에 가까운 노이즈를 일부 제거했다. 원본의 전경색과 알파를 각각 알아낸 것은 아니다. 로고가 회색 불투명인지 흰색 반투명인지 검정 샘플 한 종류로 판별할 수 없다. 검정 그림자는 복원되지 않았다.

원본 전체 줄과 출현별 분해를 같은 알파 모델로 처리했다. 이를 원래 위치에 붙였을 때 같은 밝기 결과가 나오는지 검증했다. 이는 동적 문자열이나 밝은 사진에서 원본과 동일하다는 뜻이 아니다.

## 관찰된 배치

- 날짜의 첫 숫자에서 밝기 80 초과인 첫 잉크 픽셀은 x=175다.
- 날짜 잉크의 상단은 y=2451이다.
- 날짜/시간 전체 출현 좌표는 샘플별 manifest를 따른다.
- 시간의 잉크 상단과 하단은 `오전`/`오후` 및 숫자 모양에 따라 다르다. 잉크 상단을 일괄 정렬하면 글자가 흔들릴 수 있으므로 실제 기준선을 찾아야 한다.
- x=175, y=2451은 잉크 경계이지 폰트 프레임 원점이나 베이스라인이 아니다.
- 긴 날짜도 시작 위치가 같으며 폭이 오른쪽으로 늘어난다. 한 자리 월·일 샘플도 포함했다.
- 정확한 폰트 크기, 논리적 글자 진행 폭, 커닝, 공백 폭, 소수 픽셀 위치는 아직 측정값이 없다. JSON의 `null`을 임의로 확정값처럼 사용하지 않는다.

## 다음 구현 순서 제안

1. 이 문서와 JSON을 읽고 검증 스크립트를 실행한다.
2. 패키지의 출현별 자산을 원래 좌표에 조립해, 샘플 8장의 레이아웃을 복원한다.
3. 실제 폰트 후보를 비교하거나 이미지 글자 조합 방식을 계속 사용할지 판단한다. 동일한 폰트를 찾기 전에는 유사 폰트로 조용히 교체하지 않는다.
4. 여러 출현의 좌표를 이용해 글자별 진행 폭, 앞뒤 여백, 숫자 쌍 간격, 공백 폭과 기준선을 추정한다. 글자의 PNG 폭만큼 단순히 이어 붙이지 않는다.
5. 날짜와 시간 문자열 포맷터를 렌더링과 분리한다. 원래 입력은 날짜·시간 구조로 보존하고 요일과 오전/오후는 계산한다.
6. 렌더러는 기준 3240px 좌표에서 합성한 후, 최종 출력 크기로 한 번만 축소한다. 미리보기 표시 크기가 저장 해상도를 결정하지 않게 한다.
7. 새로운 날짜는 기존 샘플의 일부를 학습에서 제외한 뒤 재조합해 비교한다. 이미지를 원래 자리에 붙이는 것만으로 검증을 끝내지 않는다.
8. 사용자가 플랫폼을 정하면 사진 선택, 날짜·시간 입력, 미리보기, 저장 UI에 연결한다.

## 날짜·시간 규칙

- 날짜: `YYYY년 M월 D일 (요일)`; 월과 일은 앞에 0을 붙이지 않는다.
- 시간: `오전/오후 h:mm`; 시는 앞에 0을 붙이지 않고 분은 2자리다.
- 00:08 → 오전 12:08, 12:34 → 오후 12:34, 23:49 → 오후 11:49.
- 기본 사용 문맥은 한국이고 샘플은 Asia/Seoul 현지 시각이다. 입력의 시간대 정책은 구현 시 명시한다.
- 잘못된 날짜는 거부한다. 윤년과 월별 일수 및 요일 계산은 표준 날짜 라이브러리를 사용한다.
- 연도 범위는 아직 합의되지 않았다. 일반적인 4자리 연도를 우선 고려하되 최종 결정으로 간주하지 않는다.

## 완료 기준

- 임의 날짜·시간 변경 및 올바른 요일/오전·오후 표시.
- 숫자와 한글의 기준선, 자간, 두 줄 간격, 로고 위치 비교.
- 샘플 8장 각각과 재조합 결과의 차이 이미지 및 수치 결과.
- 최소 1080px, 1536px, 3240px 출력에서 배치가 비례하고 저장이 정상 동작.
- 원본 사진과 출력 사진을 별도로 유지한다.
- 밝은 배경의 그림자·알파는 미확인임을 개발 문서에 유지한다. 가시적 차이가 남으면 그대로 보고한다.

## 흰 배경 샘플이 나중에 필요할 때

우선 현재 자료로 진행한다. 그림자나 밝은 배경 오차가 실제로 문제가 될 때만 추가 샘플을 요청한다. 카메라로 흰 종이를 찍기보다, 순백색 이미지(RGB 255,255,255)를 앱에서 불러와 같은 스탬프를 합성하는 방법이 비교에 유리하다. 월요일 검정 샘플과 같은 2026-11-09 20:47, 같은 해상도·설정이면 좋다. 사용자가 아직 이 자료를 제공하지 않았다는 점을 기록한다.
