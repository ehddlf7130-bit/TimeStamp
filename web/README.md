# 타임스탬프 웹 (모바일)

순찰 사진에 한국 날짜·시각과 원본 TIME STAMP 로고를 넣는 정적 웹 앱입니다. 사진은 브라우저 안에서 처리하며 외부 서버로 보내지 않습니다. 순찰 촬영 사진과 진행 상태는 IndexedDB에 저장합니다.

## 배포 주소

[타임스탬프 웹 앱 — GitHub Pages](https://ehddlf7130-bit.github.io/TimeStamp/)

공개 GitHub 저장소에서 GitHub Pages로 배포하며 로그인 없이 접속할 수 있습니다. 사진과 순찰 기록은 접속 주소별 브라우저 저장소에 보관되므로, 이전 Sites 주소에서 찍은 사진은 해당 주소에서 별도로 내보내야 합니다.

## 화면

- **계산기**: 출발 5분 뒤부터 종료까지 필요한 사진 수를 계산합니다. 날짜와 시간을 스탬프 찍기·순찰 촬영으로 전달할 수 있습니다.
- **스탬프 찍기**: 갤러리 사진을 계획된 5분 간격 시각에 순서대로·랜덤·수동 배치합니다. 기본은 1:1 사진이며, 다른 비율은 가운데 자르기 옵션을 켜면 사용할 수 있습니다. JPG·PNG와 ZIP 내보내기를 지원합니다.
- **순찰 촬영**: 정한 순찰 계획의 시각을 순서대로 찍습니다. **23:00~23:30**으로 설정하면 셔터를 누를 때마다 **23:05 → 23:10 → 23:15 → 23:20 → 23:25 → 23:30**으로 바로 넘어갑니다. 현재 시각과 관계없이 기다리지 않고 연속 촬영할 수 있습니다.
  - 뷰파인더에는 다음 사진에 찍힐 계획 시각이 미리 보입니다. 저장이 완료되면 다음 시각으로 넘어가며, 저장 실패 시에는 같은 시각을 유지합니다.
  - 시간 띠를 눌러 원하는 시각을 선택할 수 있습니다. 이미 찍은 시각을 다시 찍으면 그 사진만 교체하고 다음 미촬영 시각으로 돌아갑니다.
  - 마지막 계획 시각까지 찍으면 보관함으로 이동합니다. 사진·보관함·ZIP 파일명은 모두 계획 시각을 사용합니다. 자정을 넘으면 날짜도 다음 날로 바뀝니다.
  - 카메라 화면은 가운데 정사각형으로 잘라 저장합니다. 보관함으로 이동하거나 화면을 숨기면 카메라를 해제합니다.
  - 새로고침하면 저장된 순찰과 사진을 복원하고 다음 미촬영 시각부터 이어 찍습니다. 이전 버전에서 실제 시각으로 찍은 사진도 그대로 보관합니다. 새 순찰을 시작하면 이전 사진을 삭제하므로 먼저 내보내세요.
- **스탬프 디자인**: 저장된 `TimeStamp-v1.1`의 로고 PNG, 글자 PNG, 자간·좌표, 그림자 설정을 그대로 사용합니다. 브라우저 시스템 글꼴이나 임의의 시계 그림으로 대체하지 않습니다. 새 디자인은 새로 촬영한 사진과 일괄 내보내기에 적용됩니다. 이미 합성되어 보관함에 저장된 사진은 다시 촬영해야 디자인이 바뀝니다.

지원되는 휴대폰에서는 **모두 저장 (공유)** 후 **이미지 저장**을 선택해 사진 앱으로 보낼 수 있습니다. 일괄 렌더링 후에는 화면 아래 **저장**을 한 번 더 누릅니다. 파일 공유를 지원하지 않는 브라우저는 ZIP 다운로드를 이용하세요. 브라우저 데이터 삭제·저장 공간 정리 시 사진이 사라질 수 있으므로 중요한 사진은 내보내세요.

## 개발과 검증

Node.js 22.12 이상을 사용합니다. Windows PowerShell에서 `npm` 실행 정책 오류가 나면 `npm.cmd`로 실행하세요.

```powershell
cd web
npm ci
npm test
npm run build
npm run verify
npm run dev
```

- `dev`: HTTPS 개발 서버입니다. 같은 Wi-Fi의 휴대폰에서 PC 주소로 접속할 수 있습니다. 카메라는 HTTPS 또는 localhost에서 사용할 수 있습니다.
- `build`: 원본 자료에서 `public/stamp/`를 생성하고 타입 검사 후 `dist/`에 배포 파일을 만듭니다. `handoff/timestamp_codex_handoff`와 `src/TimeStamp.App`의 JSON 설정을 사용하며 Windows 앱 빌드는 필요하지 않습니다.
- `test`: 날짜 계산, 배치, 계획 시각 순차 진행과 자정 경계, 그림자, 실측 글리프 좌표, v1.1 자산·설정 43개의 SHA-256을 검사합니다.
- `verify`: 먼저 빌드해야 합니다. Edge/Chrome 또는 설치한 Chromium으로 렌더링과 **프로덕션 파일**을 검사합니다. 원본 v1.1 실행 파일이 생성한 기준 PNG 12장과 픽셀을 비교합니다. 3240px 기준 출력은 스탬프 영역 평균 오차 0.5/255 미만·최대 채널 오차 10/255 이내를 요구합니다. 실제 최대 오차는 Windows Edge 1/255, Linux Chromium 8/255로, 같은 PNG를 그릴 때의 가장자리 보간 차이를 반영한 범위입니다. 축소 출력에도 WPF와 브라우저의 필터 차이를 허용합니다. `/TimeStamp/` 경로에서 계획 시각 연속 촬영, 저장 실패 시 사진·진행 상태 롤백, 다시 찍기, 새로고침 복원, 촬영 완료, 자정 날짜 변경, 이전 사진 보존, JPG·PNG ZIP, 순서·수동·랜덤 배치도 검사합니다. 가상 카메라와 합성 사진을 사용하며 개인 사진은 필요하지 않습니다. 결과와 스크린샷은 `web/.checks/`에 남깁니다.

브라우저가 없으면 `npx playwright-core install --with-deps chromium`을 실행하거나 `BROWSER` 환경 변수에 실행 파일 경로를 지정하세요. 자동 검증은 Chromium 기준입니다. iPhone Safari의 실제 카메라 권한, 홈 화면 실행, 사진 공유 시트는 기기에서 추가로 확인해야 합니다.

`scripts/build-stamp-data.mjs`는 v1.1과 동일한 글리프·로고 PNG, 배치·그림자 설정을 웹용으로 생성합니다. 개발 실행·단위 테스트·빌드에서 자동 실행됩니다. 기준 출력과 원본 해시는 `tests/fixtures/v1.1/`에 보관하며 디자인 회귀를 배포 전에 검사합니다.

## GitHub 업로드와 배포

`main`에 push하거나 PR을 만들면 `.github/workflows/pages.yml`이 설치·테스트·빌드·브라우저 검증을 실행합니다. `dist`와 `node_modules`, 검증 결과는 소스로 업로드하지 않습니다.

현재 저장소에서는 GitHub Pages와 `ENABLE_PAGES=true`가 활성화되어 있어 `main`의 웹 변경 사항을 검증한 뒤 자동 배포합니다. 다른 저장소에서 사용할 때는 다음을 설정하세요.

1. 저장소 Settings → Pages → Source를 **GitHub Actions**로 선택합니다.
2. Settings → Secrets and variables → Actions → Variables에 `ENABLE_PAGES` 값을 `true`로 만듭니다.
3. Actions에서 **Web checks and GitHub Pages**를 수동 실행하거나 `main`에 push합니다.

비공개 저장소에서 Pages가 제공되지 않는 경우에도 CI는 실행됩니다. `web/dist/`를 HTTPS를 지원하는 다른 정적 호스팅에 배포할 수도 있습니다. 주소를 iPhone Safari에서 열고 공유 → **홈 화면에 추가**로 등록할 수 있습니다. 서비스 워커가 없으므로 오프라인 실행은 지원하지 않습니다.
