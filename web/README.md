# 타임스탬프 웹 (모바일)

순찰 사진에 한국 날짜·시각과 문구를 넣는 정적 웹 앱입니다. 사진은 브라우저 안에서 처리하며 외부 서버로 보내지 않습니다. 순찰 촬영 사진과 진행 상태는 IndexedDB에, 스탬프 문구는 localStorage에 저장합니다.

## 배포 주소

[타임스탬프 웹 앱 — GitHub Pages](https://ehddlf7130-bit.github.io/TimeStamp/)

공개 GitHub 저장소에서 GitHub Pages로 배포하며 로그인 없이 접속할 수 있습니다. 사진과 순찰 기록은 접속 주소별 브라우저 저장소에 보관되므로, 이전 Sites 주소에서 찍은 사진은 해당 주소에서 별도로 내보내야 합니다.

## 화면

- **계산기**: 출발 5분 뒤부터 종료까지 필요한 사진 수를 계산합니다. 날짜와 시간을 스탬프 찍기·순찰 촬영으로 전달할 수 있습니다.
- **스탬프 찍기**: 갤러리 사진을 계획된 5분 간격 시각에 순서대로·랜덤·수동 배치합니다. 기본은 1:1 사진이며, 다른 비율은 가운데 자르기 옵션을 켜면 사용할 수 있습니다. JPG·PNG와 ZIP 내보내기를 지원합니다.
- **순찰 촬영**: 셔터를 누른 순간의 **실제 한국 시각**을 기록합니다. 사진에는 분까지 표시하고, 보관함과 파일명에는 초까지 표시합니다. 같은 시각에 여러 번 찍어도 사진을 모두 보관합니다.
  - 각 계획 시각 앞뒤 2분 30초 안의 촬영은 해당 시각을 확인합니다. 두 시각의 정확한 중간은 뒤쪽 시각으로 배정합니다.
  - 확인된 시각·빠진 시각·다음 촬영까지 남은 시간을 보여 줍니다. 순찰 시간 밖의 사진도 보관하지만 시각 확인에는 포함하지 않습니다.
  - 카메라 화면은 가운데 정사각형으로 잘라 저장합니다. 보관함으로 이동하거나 화면을 숨기면 카메라를 해제합니다.
  - 새로고침하면 저장된 순찰과 사진을 복원합니다. 새 순찰을 시작하면 이전 사진을 삭제하므로 먼저 내보내세요.
- **스탬프 문구**: 두 사진 화면에서 공유하며 다시 접속해도 기억합니다. 비우면 오른쪽 위에 시계만 찍힙니다.

지원되는 휴대폰에서는 **모두 저장 (공유)** 후 **이미지 저장**을 선택해 사진 앱으로 보낼 수 있습니다. 일괄 렌더링 후에는 화면 아래 **저장**을 한 번 더 누릅니다. 파일 공유를 지원하지 않는 브라우저는 ZIP 다운로드를 이용하세요. 브라우저 데이터 삭제·저장 공간 정리 시 사진이 사라질 수 있으므로 중요한 사진은 내보내세요.

## 개발과 검증

Node.js 22.12 이상을 사용합니다. Windows PowerShell에서 `npm` 실행 정책 오류가 나면 `npm.cmd`로 실행하세요.

```powershell
cd web
npm ci
npm test
npm run build
npm run verify
npm run dev
```

- `dev`: HTTPS 개발 서버입니다. 같은 Wi-Fi의 휴대폰에서 PC 주소로 접속할 수 있습니다. 카메라는 HTTPS 또는 localhost에서 사용할 수 있습니다.
- `build`: 타입 검사 후 `dist/`에 배포 파일을 만듭니다. 글리프 자료나 Windows 앱 빌드는 필요하지 않습니다. 현재 스탬프는 기기의 한글 폰트와 캔버스로 그립니다.
- `test`: 날짜 계산, 배치, 실제 촬영 시각과 확인 범위, 그림자와 문구를 검사합니다.
- `verify`: 먼저 빌드해야 합니다. Edge/Chrome 또는 설치한 Chromium으로 렌더링과 **프로덕션 파일**을 검사합니다. `/TimeStamp/` 경로에서 앱 시작, 촬영, 중복 촬영, 새로고침 복원, 문구 동기화, JPG·PNG ZIP, 순서·수동·랜덤 배치를 검사합니다. 가상 카메라와 생성한 사진을 사용하며 개인 사진은 필요하지 않습니다. 결과와 스크린샷은 `web/.checks/`에 남깁니다.

브라우저가 없으면 `npx playwright-core install --with-deps chromium`을 실행하거나 `BROWSER` 환경 변수에 실행 파일 경로를 지정하세요. 자동 검증은 Chromium 기준입니다. iPhone Safari의 실제 카메라 권한, 홈 화면 실행, 사진 공유 시트는 기기에서 추가로 확인해야 합니다.

`scripts/build-stamp-data.mjs`는 예전 Windows 글리프 자료 재생성을 위해 보존했으며, 현재 웹 앱 빌드에는 사용하지 않습니다.

## GitHub 업로드와 배포

`main`에 push하거나 PR을 만들면 `.github/workflows/pages.yml`이 설치·테스트·빌드·브라우저 검증을 실행합니다. `dist`와 `node_modules`, 검증 결과는 소스로 업로드하지 않습니다.

현재 저장소에서는 GitHub Pages와 `ENABLE_PAGES=true`가 활성화되어 있어 `main`의 웹 변경 사항을 검증한 뒤 자동 배포합니다. 다른 저장소에서 사용할 때는 다음을 설정하세요.

1. 저장소 Settings → Pages → Source를 **GitHub Actions**로 선택합니다.
2. Settings → Secrets and variables → Actions → Variables에 `ENABLE_PAGES` 값을 `true`로 만듭니다.
3. Actions에서 **Web checks and GitHub Pages**를 수동 실행하거나 `main`에 push합니다.

비공개 저장소에서 Pages가 제공되지 않는 경우에도 CI는 실행됩니다. `web/dist/`를 HTTPS를 지원하는 다른 정적 호스팅에 배포할 수도 있습니다. 주소를 iPhone Safari에서 열고 공유 → **홈 화면에 추가**로 등록할 수 있습니다. 서비스 워커가 없으므로 오프라인 실행은 지원하지 않습니다.
