# 타임스탬프 · 순찰 사진 도우미

Windows 데스크톱 프로그램입니다. 순찰에 필요한 사진 수를 계산하고, 사진을 5분 간격의 시간에 배치한 뒤 한국어 날짜·시간과 TIME STAMP 로고를 합성합니다. 사진 처리는 PC 안에서 이루어집니다. 서버, 계정, 인터넷 연결이 필요하지 않습니다.

## 실행

웹 버전은 `web/`에 있습니다. `web` 폴더에서 `npm ci`, `npm test`, `npm run build`를 실행하면 정적 배포 파일이 `web/dist/`에 생성됩니다. 개발 실행, 모바일 촬영과 GitHub Pages 설정은 [웹 안내](web/README.md)를 참고하세요.


음영 보정 버전은 `release/TimeStamp-v1.1/TimeStamp.exe`를 실행하세요. 다른 위치로 옮길 때는 `TimeStamp-v1.1` 폴더 전체를 옮기거나 `release/TimeStamp-Windows-v1.1.zip`을 풀어 사용하세요. 실행 파일만 옮기면 글자 리소스를 찾을 수 없습니다. 기존 `release/TimeStamp` 버전은 그대로 보존했습니다.

.NET 9 Windows Desktop Runtime이 필요합니다. 개발·검증한 현재 PC에는 설치되어 있습니다. 별도 설치 프로그램을 실행하거나 시스템 설정을 바꾸지 않습니다.

## 사용 순서

1. **순찰 계산기**에서 순찰을 시작하는 날짜와 시작·종료 시각을 입력합니다.
2. **계산하기** 또는 간편 계산을 누릅니다. 자동 입력을 체크한 채 **스탬프 찍기 →**를 누르면 계산한 날짜와 시간으로 이어집니다. 자동 입력 체크를 끄면 스탬프 단계의 기존 입력을 유지합니다.
3. **스탬프 찍기**에서 시간을 직접 입력할 수도 있습니다. 변경한 뒤 **시간 적용**을 누르세요.
4. **여러 장 선택**으로 사진을 한꺼번에 불러옵니다. 사진 영역에 파일을 끌어와도 됩니다.
5. **순서대로** 또는 **랜덤 배치**를 선택합니다. 자동 배치는 선택 사항입니다.
6. 수동으로 배치하려면 왼쪽에서 사진을, 가운데에서 시간을 선택하고 **선택 사진을 이 시간에 배치**를 누릅니다. 다른 시간에 이미 배치된 사진이면 두 시간의 사진을 서로 바꿉니다. **이 시간 비우기**로 배치를 해제할 수 있습니다.
7. 모든 시간에 사진을 배치한 후 출력 해상도와 형식을 선택하고 **사진 내보내기**를 누릅니다.

## 계산과 날짜 규칙

| 순찰 구간 | 첫 사진 | 마지막 사진 | 필요한 사진 |
| --- | --- | --- | --- |
| 00:00~00:30 | 00:05 | 00:30 | 6장 |
| 00:30~01:00 | 00:35 | 01:00 | 6장 |
| 00:00~01:00 | 00:05 | 01:00 | 12장 |
| 20:00~다음 날 01:00 | 20:05 | 다음 날 01:00 | 60장 |

- 출발 시각에는 사진을 세지 않습니다. 출발 5분 뒤부터 5분마다 한 장씩, 종료 시각을 포함합니다.
- 첫 사진과 마지막 사진을 정확히 맞추기 위해 총 순찰 길이는 5분 단위로 입력합니다. 예를 들어 00:00~00:32는 종료 시각을 조정하라는 메시지가 나옵니다.
- 종료 시각이 시작 시각보다 이르면 다음 날로 계산합니다. 같은 시각은 잘못된 입력으로 처리합니다.
- 입력 시각은 PC 시간대와 관계없이 한국 현지 시각으로 취급합니다. 기본 날짜는 한국의 오늘 날짜입니다.
- 20:00~다음 날 01:00 밖의 시간이 포함되면 경고하고, 입력한 시간으로 진행할 수 있습니다.
- 시작 날짜는 1000~9998년입니다. 자정을 넘긴 사진의 날짜·요일은 자동으로 바뀝니다.
- 사진보다 시간이 많으면 빈 시간을 표시하고 출력을 막습니다. 사진이 더 많으면 초과 사진은 대기합니다. 랜덤 배치는 사진과 시간 모두 중복 없이 배치합니다.
- 시간 범위를 바꾸면 날짜와 시각이 정확히 일치하는 기존 배치를 유지합니다. 나머지 사진은 사진 목록에 남습니다.

## 사진과 출력

- 가로와 세로 픽셀 수가 같은 **1:1 사진만** 불러옵니다. 한 변 최대 12,000픽셀입니다. 비율이 다른 사진을 임의로 자르지 않습니다.
- JPG/JPEG, PNG, BMP, TIF/TIFF를 지원합니다. HEIC는 지원 형식에 포함하지 않습니다.
- 같은 파일 경로를 다시 선택하면 중복 추가하지 않습니다. 잘못된 파일은 건너뛰고 목록을 알려줍니다.
- JPEG의 EXIF 회전 정보를 반영해 화면과 출력 방향을 맞춥니다.
- 미리보기는 640픽셀이며, 저장 해상도와 독립적입니다. 출력은 **원본 크기 / 1080 / 1536 / 3240**을 선택할 수 있습니다.
- 출력 형식은 **JPG 폴더 / PNG 폴더 / JPG ZIP**입니다. JPG 품질은 95입니다.
- 폴더 출력은 선택한 위치 안에 새 결과 폴더를 만듭니다. ZIP은 저장 위치를 직접 선택합니다. 실패한 ZIP으로 기존 결과를 덮어쓰지 않습니다.
- 결과 이름은 `001_20261109_2335.jpg`와 같습니다. 시간 순서로 번호를 붙이며 자정 이후에는 날짜도 바뀝니다.
- 원본 파일을 수정하거나 삭제하지 않습니다. 사진 목록에서 제외하는 동작은 앱의 목록에서만 제거합니다. 앱을 종료하면 입력과 배치는 초기화됩니다.

## 스탬프 디자인

사용자가 제공한 ZIP의 로고·글자 PNG를 사용합니다. 일반 폰트로 대체하지 않았습니다. 날짜는 `YYYY년 M월 D일 (요일)`, 시간은 `오전/오후 h:mm`입니다.

3240픽셀 기준 좌표에서 로고와 글자를 배치하고 최종 출력 크기에 맞춰 그립니다. 글자의 진행 폭과 공백은 8개 샘플의 측정 좌표에서 추정했습니다. `tools/calibrate-layout.cjs`로 다시 계산할 수 있습니다. 각 글자의 세로 위치는 원본에서 추출한 위치를 보존합니다.

v1.1에서는 제공된 `Orginal.jpg`(1080×1080)와 `Program.jpg`(3024×3024)를 같은 크기로 맞춰 비교하고, **글자와 로고 뒤의 넓고 옅은 검정 음영**을 추가했습니다. 사진 전체의 밝기를 바꾸지 않고 스탬프의 알파 모양을 따라 그림자를 만듭니다. 기준 3240픽셀에서 글자는 Gaussian sigma 35.25픽셀·불투명도 0.3787, 로고는 sigma 45픽셀·불투명도 0.2983이며 `stamp-style.json`에 기록했습니다. 해상도에 비례해 같은 모양으로 출력합니다. 미리보기와 실제 저장에 같은 렌더러를 사용합니다.

원본 폰트와 실제 알파는 여전히 확인되지 않았고, 음영은 이번 사진 쌍에서 추정한 값입니다. 원본과 같은 크기로 비교하려면 출력 해상도 **1080×1080**을 선택하세요. JPEG 압축과 축소 필터, 글자 가장자리·자간에 남는 차이 때문에 완전한 픽셀 일치를 보장하지 않습니다. 기존에 스탬프가 찍힌 사진을 입력하면 새 스탬프가 추가됩니다.

## 소스 구조

- `src/TimeStamp.Core`: 순찰 시간 계산, 한국어 날짜·시간 표기, 사진 배치 규칙.
- `src/TimeStamp.App`: WPF 화면, 사진 읽기, PNG 글자 합성, 폴더·ZIP 출력.
- `tests/TimeStamp.Checks`: 외부 테스트 패키지가 필요 없는 핵심 동작 검증.
- `handoff/timestamp_codex_handoff`: 제공 ZIP의 원본 추출 자료. 문서는 설계 참고 자료로 취급했으며 현재 요청을 우선했습니다.
- `artifacts/render-checks`: 검증 결과, 합성 예시, 화면 이미지, 샘플별 차이 이미지.
- `artifacts/stamp-calibration`: 원본·이전 출력·음영 보정의 확대 비교와 측정 수치. 제공 사진은 수정하지 않았습니다.
- `tools/StampCalibration`, `tools/fit-stamp-shadow.cjs`: 사진 크기 정규화, 그림자 추정, 실제 렌더러를 통한 보정 비교 도구.

## 빌드와 검증

.NET SDK 9.0.301 이상 9.0 패치 버전과 Windows Desktop 타깃 팩으로 빌드합니다. 앱에 외부 NuGet 패키지는 없습니다. `NuGet.Config`는 외부 패키지 소스를 사용하지 않도록 설정했습니다. 간격 추정 재생성에는 Node.js가 필요하지만 앱 실행에는 필요하지 않습니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/build.ps1
powershell -ExecutionPolicy Bypass -File tools/verify.ps1
```

스크립트는 이 프로세스에만 적용되는 실행 정책 옵션으로 실행합니다. 시스템 실행 정책을 변경하지 않습니다.

현재 검증: 핵심 계산·배치 37개, 이미지·UI 핸들러·일괄 출력·음영 검증 42개 통과. 첨부 자료 254개 파일의 SHA-256 일치 확인. 앱 빌드 오류·경고 0개.

이미지 검증은 3가지 해상도의 JPG/PNG 재열기, 정사각형 제한, EXIF 방향, 원본 보존, 8개 동적 날짜 샘플, 다중 입력, 중복 입력, 순서·랜덤·수동 배치, 자정 날짜, ZIP 내부 이미지 재열기, 실패 시 기존 ZIP 보존을 포함합니다. 실제 화면에서도 간편 계산과 자동 입력 전환을 확인했습니다. 파일 대화상자를 거치는 내보내기 전체 흐름은 수동 완료 검증하지 않았고, 동일한 앱 내보내기 서비스를 통합 검증했습니다.

동적 샘플과 고정 기준 이미지의 전체 프레임 평균 밝기 오차는 0.0415~0.0937/255이며, 최대 픽셀 오차는 78~169/255입니다. 배경이 대부분 검정이므로 전체 프레임 평균만으로 글자 일치를 평가하면 안 됩니다. 샘플을 하나씩 제외한 간격 추정에서는 글자 잉크의 가로 위치 평균 오차가 날짜 최대 1.124픽셀, 시간 최대 1.602픽셀(3240픽셀 기준)이었습니다. 자세한 수치와 3배 증폭 차이 이미지는 검증 산출물을 참고하세요.

이번 밝은 사진 비교에서는 1080픽셀 기준 지정 영역의 채널별 평균 절대 오차가 글자 6.4777 → 3.3273/255(48.63% 감소), 로고 6.7406 → 3.1077/255(53.90% 감소)였습니다. 스탬프 없는 입력 사진이 제공되지 않았으므로, 비교 이미지는 기존 프로그램 출력에 **새 렌더러에서 계산한 그림자만** 추가한 보정 미리보기입니다. 글자를 이중으로 찍지 않았으며, 스탬프 없는 원본에서 재출력한 사진으로 주장하지 않습니다. 측정에 사용한 사진 쌍에 대한 보정 결과이며 다른 사진에서의 픽셀 일치를 보장하는 수치는 아닙니다.

추가 검증은 검정 배경에서 기존 글자 유지, 글자·로고 양쪽 음영 생성, 스탬프와 무관한 영역 보존, 음영의 밝기 증가 방지, 1080·3240 해상도 간 비례를 확인합니다. `artifacts/shadow-checks/results.txt`에 결과를 보관합니다.
